# 变更提案

## Why（背景与动机）

本变更在新的定制仓库保留 `main` / `custom` 两个长期分支，提供手动多平台打包和可选的端到端加密凭据恢复，减少多设备重复授权。

## What Changes（变更内容）

- 远端长期仅保留 `main` 和 `custom`；本地开发和上游更新使用临时 `codex/*` 分支，合并后删除。
- 每小时和推送到 `custom` 时检查官方 `main` 最新提交；没有更新时，不创建分支或 PR。有待处理同步 PR 时复用，不能覆盖人工冲突修复。
- 上游更新通过 PR 集成到 `custom`，合并前在本地验证；PR 不触发 Actions。定时检查不打包，手动打包前核对所选提交包含检查时官方 `main` 最新提交。
- 手动从 `custom` 为 Windows x64、Linux x64、macOS arm64 打包，使用新仓库的更新地址、发布元数据及 Tauri 更新签名。
- 建立独立凭据同步服务，提供设备登记、配对、心跳、密文备份、恢复协调、版本检查和设备撤销。
- 从 Codex 账号页配置同步。已有可信设备可生成、查看、复制和更换长期配对码；其他设备填写服务器地址及同一码即可加入，无需在线审批。全新同步库仍须先验证服务器所有者身份。
- Codex OAuth 凭据采用端到端加密，服务器只能保存和转发密文，无法解密。
- 仅在添加账号、完成重新授权或用户手动上传时主动备份；普通 Token 自动刷新不触发上传。
- 本地出现明确授权失败时，优先询问合适的在线设备，再使用服务器密文备份；原来的安全操作最多自动重试一次。
- 在线恢复不依赖手动上传。恢复成功立即更新 Codex 账号页，不要求重启 Cockpit Tools；账号页也提供一次恢复多个异常账号的入口及逐项结果。
- 候选凭据耗尽，或备份过旧、无效时，结束本轮恢复；仅在下次启动或手动同步时开启新一轮。
- 同步服务不可用时保留本地功能；防止过期恢复结果覆盖本地删除、重新授权、凭据代次或运行实例状态。

## Capabilities（能力范围）

### New Capabilities（新增能力）

- `upstream-maintenance`：检测官方更新，维护 `main` / `custom`，创建、合并和删除临时更新分支，并以检查结果约束发布。
- `custom-release-packaging`：从定制分支手动构建和发布三个平台的签名安装包。
- `codex-credential-recovery`：设备配对、端到端加密的 Codex OAuth 凭据上传、在线设备协助恢复、密文备份兜底及有界重试。

### Modified Capabilities（修改现有能力）

无。

## Impact（影响范围）

- fork 的 GitHub Actions、分支保护、发布脚本、更新配置和签名密钥。
- 新建私有凭据同步服务仓库，包含 HTTPS API、SQLite 数据结构、部署配置和协议测试。
- Tauri / Rust 的 Codex 账号生命周期、凭据代次、存储锁、启动和后台协调，以及新增 IPC 命令。
- React 设置及账号界面，提供服务器配置、设备配对、手动同步与上传、恢复状态和设备撤销。
- Rust / TypeScript 测试、多设备集成测试，以及真实设备上的发布验收。
