# 技术设计

## Context（当前背景）

本仓库为 Tauri 桌面应用，使用 React 界面和 Rust 账号生命周期逻辑。Codex 账号详情已在本地加密；凭据代次与删除标记能够保护写入；既有权威凭据采集和刷新路径区分重新授权与普通配额查询。定制版本转移到独立仓库，发布由维护者手动触发。外部行为以 proposal 和 capability 规格为准。

## Goals / Non-Goals（目标与非目标）

**目标：**

- 隔离定制逻辑，保持薄 fork；远端长期只保留 `main` 和 `custom`。
- 上游检查不产生重复 PR，明确合并、构建、签名和发布的检查门槛。
- 建立可独立部署的凭据同步服务，服务器只保存经过认证的密文。
- 在明确授权失败和授权成功边界接入恢复、上传，不改变普通 Token 刷新行为。
- 保留本地账号安全、离线能力、删除语义，以及准确的运行实例就绪状态。

**非目标：**

- 同步全部 Cockpit 设置、实例、项目、聊天记录、API Key 或任意文件。
- 替代 Codex 原生 OAuth，或保证多设备同时运行时永远不会出现 refresh token 轮换冲突。
- 自动重放已经输出内容、执行工具或执行状态不明的操作。
- 第一版建设通用多租户凭据保险库或管理网站。

## Decisions（设计决策）

### 客户端 fork 与同步服务分别建仓

桌面端 fork 与凭据服务使用独立仓库。客户端负责本地加密、设备密钥、账号身份映射和恢复决策；服务端负责经过认证的传输、设备登记、密文备份元数据、租约及有界恢复协调。两者可以分别部署、回滚，服务端更新无需伴随每次桌面版本发布。

曾考虑 WebDAV 文件方案，但它不适合表达设备配对、候选凭据、租约、撤销或并发条件写入，因此不用于恢复协调。

### 两个长期分支与临时更新分支

`main` 保留官方代码和提交历史，移除可执行的上游 Actions 定义；默认分支 `custom` 承载定制开发和发布。维护者按需检查官方正式版本，通过祖先关系判断是否已集成。没有新版本不创建分支或 PR；已有待合并的更新继续处理。集成使用保留祖先关系的 merge commit。合并前本地验证，合并后由仓库设置删除临时分支。两个长期分支均不执行 PR 或定时工作流。

### 手动打包

维护者从 `custom` 手动触发，固定提交 SHA，只构建 Windows x64、Linux x64 和 macOS arm64。macOS 使用临时签名，无需 Apple Developer ID 或公证；保留各平台的 Tauri 更新签名。最终发布串行化，防止较旧任务覆盖最新更新清单。三个目标的构建、签名、来源、清单和校验和均通过验证后公开 Release，草稿仅用于上传暂存。

现有 tag 流程和版本校验要求三段数字。定制渠道预留 `2.0.N`（当前观察到的上游版本为 1.4.0）：N 取受保护 `custom` 的 first-parent 提交数，由串行合并顺序决定，无需共享可变计数器；固定 SHA 重跑复用相同版本。最终创建发布仍串行化，禁止修改不同源码或已经公开的同版本发布。仅在隔离打包工作区生成 package.json、锁文件中的包元数据、Tauri 配置和 Cargo 版本变更；不要向 `custom` 提交纯版本更新，避免递归构建。上游版本与 SHA 单独记录。tag 指向准确源提交，构建来源元数据包含生成后的打包输入清单。现有 tag / 包版本校验及更新日志提取需要适配“源提交 + 构建版本”模式。

更新地址和发布链接迁移到 `Mickls/cockpit-tools-custom`，沿用原定制版的 Tauri 更新签名公钥。旧客户端内置了旧仓库地址，首次切换需要从新仓库手动覆盖安装；以后由新地址提供自动更新。密钥仅提供给新仓库 `custom` 上的手动构建。

### 服务器不接触明文凭据

每个同步库生成随机对称内容密钥；使用设备公钥为已配对设备封装该密钥。凭据载荷经过认证加密，并由发送设备签名。服务器只能看到不透明账号标识、版本、设备 ID、过期时间、签名和密文，不持有 OAuth 解密能力。

采用持续维护的 AES-256-GCM 载荷加密、基于 X25519 的标准密钥封装、Ed25519 设备签名、HKDF 域分离实现，不自行设计密码原语。与可轮换内容密钥分离的随机查询密钥用于派生账号 HMAC。签名绑定账号标识、同步库及设备身份、密钥代次、载荷摘要、父版本，以及可选的恢复请求和接收方 ID；AEAD 附加认证数据绑定相同不可变头部。同一密钥下随机 nonce 不得重复。私钥存入本地安全存储，不经 React 传输。

稳定账号身份由规范化后的供应商 / 发行方、用户主体、ChatGPT 账号、可选组织、认证类型组成。现有包含邮箱的 MD5 本地 ID 不能直接作为全局身份。字段缺失或歧义时，界面要求显式绑定，而不是只按邮箱匹配。解码声明仅用于比对；接受候选前仍需真实上游授权验证。

首台设备本地生成同步库与恢复密钥。已有设备通过核对指纹、签署成员身份，并向新设备公钥封装密钥，批准有时限的配对请求。无可信设备在线时，用恢复密钥在本地解密恢复包；服务端设备登记鉴权单独处理。客户端固定可信签名成员关系，不能接受服务器任意插入的公钥。撤销设备后停止服务访问，推进已签名成员和密钥代次，并为剩余设备重新封装密钥、重新加密保留备份。已下载凭据无法远程收回。丢失恢复密钥且所有设备均丢失时，旧备份无法恢复；已被攻陷的授权终端不在端到端加密的保护范围内。

### 上传与恢复使用独立状态机

仅添加账号成功、重新授权成功或用户显式操作触发上传队列。队列有界、幂等，不阻塞本地保存。普通 Token 刷新仅更新本地。

恢复协调器按账号单飞，每个账号最多一个进行中的恢复轮次。既有账号检查与刷新分类确认明确授权失败后才进入。通过租约询问其他设备，排除请求方；在本地验证候选，无可用在线候选后才尝试密文备份。网络、代理、超时、限流和服务端错误保留原始诊断，不触发凭据恢复。成功候选提交前，使用已有变更 / 刷新锁重新读取账号，校验凭据代次、指纹、删除标记和重新授权状态。

首先复用本机权威凭据采集：某个运行配置中可能已有可用新凭据。明确撤销、`invalid_grant` 或缺少可用凭据可在正常本地处理后进入恢复；单独 401 或历史展示用途的 `requires_reauth` 标记不足以触发。协助设备读取实际运行态快照，执行只读上游账号检查，不强制轮换 refresh token，不生成模型内容。无法确认健康时返回不确定，不声称健康。

默认每 30 秒心跳，90 秒未更新视为离线；认证长轮询最长 25 秒，设备休眠后可恢复。恢复总预算 60 秒，最多串行查询三台设备，再检查一份备份。所有候选检查禁止递归恢复。按账号记录失败指纹和应用启动代次；心跳、重连及定时刷新不能重置已耗尽轮次。手动同步或新一次应用启动开启新轮次，重新授权成功清除旧失败状态。启动时无需批量下载所有账号。

在线候选的独立本地代次可能小于请求设备，这不能作为拒绝依据。服务端版本表示写入顺序，不代表凭据有效性：结合指纹去重、可用的已签名版本链、上游验证，以及提交时针对请求方本地代次的比较交换。网络验证在锁外进行；之后按已有顺序短暂加锁，重新读取并仅合并凭据所属字段，保留所有设备配置。持有账号变更锁时不得发起网络请求。保存加密的提交前恢复记录，重启时处理未完成提交，但不能用旧快照覆盖后续成功授权。上传 outbox 有界且受代次保护，延迟任务不得上传已删除或被替换的账号。

成功协助属于按需上传的特殊路径：接收方确认验证后，才按条件将该密文提升为备份当前版本；版本冲突保留现有版本，不能无条件覆盖。原操作尚未重试前，候选验证失败可在预算内切换其他来源。验证并提交成功后，只重试一次原来的安全读取；重试失败即停止，不再轮询来源。运行中 Codex 的凭据传播复用已有受支持的投影路径，无法安全更新内存状态时提示重启。

### Rust 接入边界与界面

新增 `src-tauri/src/modules/credential_sync/`，承载协议、加密、传输、设备登记、上传队列、恢复协调和本地元数据。Tauri 命令暴露配置、配对批准、手动同步 / 上传、恢复重试、设备列表及撤销。React 增加 Codex 设置区域和账号恢复状态，不接收明文 Token。

接入既有 OAuth 保存、账号检查分类、权威凭据同步、文件锁、凭据代次和删除保护路径。通用账号保存及配额写入不是上传触发点。

### 独立测试服务协议

私有服务仓库提供版本化 HTTPS 接口，覆盖配对、心跳、恢复租约 / 候选 / 结果、密文备份元数据与内容及撤销。SQLite 保存设备、同步库元数据、密文备份、恢复轮次和有保留期限的审计结果。协议样例由客户端与服务端共同测试，暂不建立第三个仓库。

服务采用 Rust / Axum / Tokio 与带迁移的 SQLite，使用 Docker Compose 单实例部署于 HTTPS 反向代理后。长轮询无需开放设备入站端口，也无需自定义 WebSocket 协议。接口包括 `POST /v1/pairings`、`POST /v1/pairings/{id}/approve`、`POST /v1/devices/heartbeat`、`GET /v1/devices/self/tasks`、`POST /v1/recoveries` 及其候选和结果接口、`GET/PUT /v1/accounts/{key}/backup`、`POST /v1/devices/{id}/revoke`。每次操作都检查同步库与设备权限，拒绝跨库 ID。签名请求使用短期 nonce、有界防重放窗口、正文摘要和幂等键。配对需要限流，并要求单独配置的初始化 / 管理员登记密钥。

逻辑数据表包括同步库、签名设备成员及密钥封装、密文备份当前版本和有限历史、幂等记录、可过期恢复任务 / 候选、审计结果。条件备份 PUT 携带前一服务版本，事务内仅推进一次；密文包含签名父版本，服务器不能改写签名载荷。服务重启使在线租约失效。载荷上限 64 KiB，每账号保留一份历史密文备份；候选五分钟内过期，运行审计元数据保留 30 天。超过默认 30 天的备份只能显式手动处理，不能自动使用。限制请求、速率和存储规模，清理传输错误，避免 Token 进入日志。

协议样例、OpenAPI、部署说明及测试命令维护在独立服务仓库。本 change 记录该外部工作及依赖；未来 apply 对服务端写入时，应使用该仓库的授权上下文。本次规划不创建服务器仓库、部署、远端分支或 GitHub 设置。

## Risks / Trade-offs（风险与取舍）

- **refresh token 轮换仍可能使其他运行设备持有的凭据失效。** → 不上传普通刷新、不为健康检查强制轮换，区分存储恢复与运行态就绪，要求真实多设备验收。
- **被撤销设备可能保留已下载的 Token。** → 轮换同步库密钥、撤销服务访问；立即失效仍需撤销上游授权。
- **上游更新可能修改定制接入点。** → 独立模块承载定制逻辑，通过显式更新 PR 与定向测试控制合并。
- **单个平台签名或打包故障阻塞发布。** → 保留验证产物和上一版本，允许直接重跑，无需再次合并提交。
- **服务故障可能被误认为账号失效。** → 保留原始本地诊断，不中断本地账号管理。
- **设备时钟偏差造成时间误判。** → 服务端版本仅表示服务内写入顺序；设备时间只用于诊断，不跨设备比较本地凭据代次。

## Migration Plan（迁移与回滚）

1. 创建新远端，配置分支和签名密钥，启用手动发布工作流。
2. 将发布元数据、更新链接切换至新仓库；手动验证安装和升级，确认数据路径保留。
3. 从空数据库部署私有同步服务，验证健康检查、密文备份恢复流程和协议 v1。
4. 客户端默认关闭同步；显式配对设备，仅上传新授权账号，观察诊断。
5. 先对少量测试账号启用恢复，完成实机多设备验收后再扩大使用。
6. 回滚时关闭同步功能并停止服务，本地账号继续工作。将旧客户端实现重新打包为更高的定制版本，不能依赖更新器降级；保留本地密钥和凭据。回滚服务端前验证数据库备份与密钥代次迁移。
